# Claude Monitor - Development Notes

## Build & Install

- Build with: `./scripts/build-macos-app.sh`
- The build script auto-detects the installed `claude-code` version (via npm) and patches the User-Agent string in `AnthropicAPI.swift` before compiling.
- **Important:** When installing to `/Applications`, you must `rm -rf` the existing app bundle before copying. `cp -R` over a running macOS app does not replace the binary. The correct sequence is:
  ```
  osascript -e 'quit app "Claude Monitor"'
  sleep 2
  rm -rf /Applications/ClaudeMonitor.app
  cp -R build/ClaudeMonitor.app /Applications/ClaudeMonitor.app
  open /Applications/ClaudeMonitor.app
  ```

## Headless / Linux

- The same package builds on Linux (`swift build` with `libsqlite3-dev` installed) as a headless daemon for Loom hosts — no UI, same poll loop, same `usage.db`/`ranking.json` outputs. See README "Headless Mode / Linux".
- UI sources are fenced with `#if os(macOS)`; portable core must stay free of AppKit/SwiftUI/Combine/os.Logger. On Linux, `LinuxCompat.swift` shims `ObservableObject`/`@Published`, and `CSQLite/` maps the system libsqlite3 (macOS uses the SDK's `SQLite3` module).
- Entry points: `main.swift` (macOS, dispatches to `HeadlessRunner` on `--headless`) and `HeadlessMain.swift` (Linux, always headless). Flags: `--once`, `--interval <sec>`, `--version`. Subcommands: `accounts`, `codex`, `selftest`. On macOS, `--version` is dispatched top-level in `main.swift` (works with or without `--headless`, never launches the GUI); bare `--once`/`--interval` (without `--headless`) fail fast with a stderr message instead of falling through to the GUI branch.
- Run the test suite with `swift build && .build/debug/ClaudeMonitor selftest` (exits non-zero on failure). CI runs it on macOS and Linux.
- To verify a schema migration against real data, copy the live DB first — `cp ~/.claude-monitor/usage.db /tmp/ && .build/debug/ClaudeMonitor selftest --db /tmp/usage.db`. `--db` **writes** to the path it is given; never point it at `~/.claude-monitor/usage.db`.
- Parse response headers via `extractAnthropicHeaders` (lowercased map), never `allHeaderFields` subscripts — those are case-sensitive on Linux.
- Verify Linux builds from macOS with the `swift:6.1` Docker image (`apt-get install libsqlite3-dev`, then `swift build`).
- **Swift 6 language mode is on package-wide** (`Package.swift`'s `swiftSettings` passes `-swift-version 6` to the `ClaudeMonitor` target — kept as an `unsafeFlags` override rather than bumping `swift-tools-version` to 6.0, so the manifest stays parseable by any 5.9+ SwiftPM). A plain `swift build` surfaces every strict-concurrency diagnostic **as long as the toolchain actually supports language mode 6** — i.e. Swift 6.0+ (Xcode 16+ on macOS, or the `swift:6.x` Linux images CI uses). This is a real toolchain constraint, not automatic: the `-swift-version 6` flag is *rejected outright* (`error: invalid value '6'`) by Swift 5.x compilers, including the macos-14 GitHub runner's **default** Xcode 15. That's why `.github/workflows/build.yml`'s `build-macos` job has a "Select Swift 6 toolchain (Xcode 16+)" step (`xcode-select` to the newest `/Applications/Xcode_16*.app`) before `swift build`; without it CI fails on the flag before compiling a single line. So: local and CI agree **once both are on a Swift-6-capable toolchain** — confirm your local `swift --version` reports 6.0+ (region-based isolation in newer point releases like 6.3.x can still *downgrade* a few diagnostics CI's pinned 6.0 hard-errors, so CI remains authoritative for the exact error/warning split). Narrowest-correct annotations are used throughout: `@MainActor` for state genuinely only ever touched from the app's one main-thread call path (`UsageStore`, `OAuthPoller`, AppKit window-controller caches, SwiftUI rows like `SummaryRow`, the CLI/headless entry points that drive them), `Sendable`/`@unchecked Sendable` for classes with real internal synchronization or no mutable state (`FileLogger`, `AnthropicAPIClient`, `OpenAIAPIClient`), and `nonisolated`/`nonisolated(unsafe)` only for pure helpers or genuinely single-threaded accumulators (documented at each site) — never a blanket suppression. Main-thread-delivered `@Sendable` closures (a `Timer` block, a `queue: .main` NotificationCenter observer) reach `@MainActor` state via `MainActor.assumeIsolated`, valid precisely because delivery is already on the main thread.

## Project Structure

- `menubar-app/ClaudeMonitor/` - Swift Package Manager project
  - `Package.swift` - Package manifest (zero package dependencies)
  - `Sources/main.swift` - macOS entry point, AppDelegate, popover/window management
  - `Sources/HeadlessMain.swift` / `Sources/HeadlessRunner.swift` - Linux entry point + UI-less poll loop (also `--headless` on macOS)
  - `Sources/LinuxCompat.swift` - `ObservableObject`/`@Published` stand-ins for Linux (no Combine)
  - `CSQLite/` - System-library target mapping Linux libsqlite3
  - `Sources/RateLimitWindow.swift` - Provider-agnostic rate-limit model (`AccountProvider`, `RateLimitWindow`, `RateLimitSnapshot`). Window kind is **derived from the window's duration**, never its position in the provider response, and every window is optional — an account may legitimately report no session window.
  - `Sources/UsageProviderClient.swift` - `UsageProviderClient` protocol + `ProviderCredentials` / `ProviderUsageSnapshot` / `ProviderAPIError` (aliased as `AnthropicAPIError`)
  - `Sources/AnthropicAPI.swift` - API client (usage, profile, token refresh); conforms to `UsageProviderClient`
  - `Sources/OpenAIAPI.swift` - OpenAI/Codex client: `GET chatgpt.com/backend-api/wham/usage` (never `/backend-api/codex/usage` — Cloudflare-challenged), `POST auth.openai.com/oauth/token` refresh, and `CodexAuth` (reads `~/.codex/auth.json`, honoring `$CODEX_HOME`). Access tokens live ~10 days; expiry comes from the token's own `exp` claim. **Never log a token or a raw response body** — `OpenAIUsageResponse.flatten` redacts PII/credential keys at *every* nesting depth before anything is archived or logged.
  - `Sources/CodexAppServer.swift` - `CodexAppServerClient`: reads Codex usage by spawning `codex -s read-only -a untrusted app-server` and speaking JSON-RPC over its stdio, so **no OpenAI credential is read, stored, or refreshed by this app**. The only place in the package that spawns a subprocess. Framing is **newline-delimited JSON** (not `Content-Length`), replies **omit the `jsonrpc` member**, notifications have no `id`, and `windowDurationMins` is **minutes** (× 60 for `RateLimitWindow`). `-32600`/`-32601` mean *capability absent → fall back*, never *account unhealthy* — codex 0.46.0 returns it for every unknown method; an unauthenticated `CODEX_HOME` returns it too, disambiguated by `account/read`'s `account == null` — a decode failure on that same reply is a distinct `.protocolFailure`, never folded into `.notLoggedIn`. (Version requirement and the Homebrew formula→cask remediation for a stale 0.46.0 install: README.md "Adding an OpenAI (Codex) Account".) The `initialize` reply's `result.userAgent` (e.g. `codex_cli_rs/0.147.0`) is read back and logged once per resolved binary path/version via `flog.info` — a cache-and-log-on-change diagnostic, not a per-poll one, so a stale-formula fallback is operator-visible in `debug.log` without spawning a separate `codex --version`. Shutdown is stdin-close → SIGTERM → SIGKILL, guaranteed on every exit path (success, throw, or cancellation) via an explicit `do`/`catch` around the handshake rather than a `defer` (a `defer` block cannot itself `await`); the wait between escalation steps suspends via `Task.sleep` rather than busy-blocking a pool thread with `usleep`. Never call `Process.waitUntilExit()` off the main thread (it spins a CFRunLoop and hangs). `codex` is resolved to an absolute path from a candidate list with a `CLAUDE_MONITOR_CODEX_BIN` override — `/usr/bin/env` fails in a Finder-launched bundle. `codexHome` is per-account (see `OAuthPoller`); a *registered* home that no longer exists on disk fails fast as `.homeMissing` **before** spawning, rather than letting codex answer `account: null` and reading as "needs login". `redactHomePath` collapses a home directory to `~` for every error string, because those strings are logged and persisted to `oauth_credentials.last_error` and a raw home path names a user.
  - `Sources/CodexCLI.swift` - `claude-monitor codex provision|add|list|import` (one-shot CLI, no `--headless` needed, works on Linux). `codex add --home <path>` registers an OpenAI account **by its `CODEX_HOME`** and stores no token — it reads only `tokens.account_id` from that home's `auth.json` (via `CodexAuth.accountId(inHome:)`, deliberately *not* `CodexAuth.load`) and asks `codex` itself for identity/usage. `codex provision <label>` (#133) collapses home-create + `codex login --device-auth` + registration into one command — it creates/reuses `~/.codex-<label>`, drives the interactive login (never automates or bypasses it), then calls the exact same `OAuthPoller.registerCodexHome`/`normalizeCodexHome` `add` uses. `codex list` reports each home's live login state, plus **absent** (#135) for a declared-but-unprovisioned identity — never probed (there is no home to ask, and asking the ambient one would report a stranger's login state as this row's) and printed with the exact `codex provision <label>` that fills the gap. All three accept `--db`. A home path is printed to stdout (that's the point of `list`) but never to `debug.log`.
  - `Sources/CLIArgs.swift` - Shared argument-parsing helpers for the one-shot subcommand CLIs (`CodexCLI`, `AccountSyncCLI`): the `--db <path>` and `--help`/`-h` option cases plus the `fail(_:) -> Never` parse-error reporter live here once (#176). A plain `enum` namespace of static pure functions, like `NaturalSort`/`PercentSeverity`.
  - `Sources/OAuthPoller.swift` - Per-provider usage polling (Anthropic ping / OpenAI usage GET), token add/import, per-account Codex-home registration, Fable probes (Anthropic only). Absent windows are stored as NULL, not 0, for non-Anthropic providers. `pollOpenAI` is a two-tier ladder ordered by how little credential handling each rung needs: `codex app-server` → bearer read from `auth.json` at request time — there is no stored-credential fallback below it (#104). A merely *unavailable* tier falls through silently; only the last tier's own failure sets a status. **Both tiers read the polled account's own `accounts.codex_home`**, resolved by `resolveCodexHome` into `.explicit` (registered home — a fresh `CodexAppServerClient` per account), `.ambient` (no registered home and no sibling that could own the inherited one), or `.ambiguous` (≥2 OpenAI accounts and this one has no home ⇒ **no** home may speak for it — both tiers are skipped and the poll reports the most actionable pending failure). Counting candidates rather than comparing emails is what closes the NULL-email attribution gap; `identitiesConflict` survives only as belt-and-braces for a re-logged-in home. **`loadActiveCredentials` is the only enumeration the poll loop uses** — it admits token-free rows (`access_token IS NULL`, `source = 'codex-home'`) whose account has a `codex_home`, or a home-registered account would never poll. **Declared identities (#135)**: `exportAccountsEnv` emits a tokenless Codex row as *identity only* (`ACCOUNT_EMAIL_N` + `ACCOUNT_PROVIDER_N` + `ACCOUNT_HOME_LABEL_N`, **no** `ACCOUNT_KEY_N`) — a home *label*, never a path, because a path names a user; `parseAccountPairs` accepts a keyless entry only for a non-Anthropic provider; `declareCodexIdentity` writes the placeholder row (no credential row at all — its absence *is* the state) and is a no-op when the identity already exists, so a paste can never downgrade a working account. `syncFromAccountFiles` honors keyless entries too — a headless Linux host has no popover, so `~/.claude-monitor/accounts.env` is its only env-transfer surface; safe on an every-launch cadence precisely because the declaration is add-only and idempotent. `openAIAccountCount` **excludes** absent rows: counting them would flip a legitimately-ambient single-account host to `.ambiguous` and stop it polling — i.e. the bookkeeping layer would break what it books.
  - `Sources/AccountFreshness.swift` - Cause-independent staleness backstop (#148): the single rule every display/ranking path uses to decide whether a reading is too old to present as current, regardless of why it stopped updating. Lives in the portable core so `UsageStore` ranking/selection, the popover freshness dot, and `SelfTest` all apply the identical threshold.
  - `Sources/SelfTest.swift` - `ClaudeMonitor selftest`: portable-core assertions (window model, schema migration, OpenAI wire mapping + PII redaction, `ranking.json` provider field) with no network/credentials. Run in CI on both macOS and Linux; there is no XCTest target because the package has zero dependencies. `--wire <path>` decodes a captured `/wham/usage` body offline (prints only derived numbers, never identity).
  - `Sources/RankingExporter.swift` - Emits `~/.claude-monitor/ranking.json`. Every account carries `provider`; `schema` stays **1** because the fields are additive. A `provider: openai` account may omit `utilization["5h"]` — consumers must read a missing key as *unknown*, never 0. An **absent** identity (#135) adds `"absent": true` and is emitted with `"status": "blocked"` and *no* `utilization`/`resets`/`updated_at`, so a consumer ignorant of the new key still excludes it from its pool.
  - `Sources/UsagePopoverView.swift` - Summary-table popover, sortable headers, add-account dialog. An **absent** row (#135) renders greyed with an `AbsentBadge` (which prints `CodexCLI.absentLabel` itself, not a second literal) and blank percentages; Copy emits Codex accounts identity-only, and Paste's replace semantics are armed **only** by credentialed entries — a declaration must never delete a provisioned home.
  - `Sources/PercentSeverity.swift` - Severity band for a percent-used value; centralizes the >95 / >=90 boundaries so the popover table, chart window, and menu-bar icon can't drift out of sync.
  - `Sources/UsageChartView.swift` - Per-account usage-history chart window
  - `Sources/RollTokenView.swift` / `Sources/TokenRoller.swift` - Roll Token wizard + revoke-script generator. The workflow depends on undocumented, web-session-cookie-authenticated `claude.ai/api/oauth` endpoints; if they change, `TokenRoller.revokeAllScript` is the single place to update (see README "Rolling a Token").
  - `Sources/UsageStore.swift` - SQLite-backed data store, account/usage models. `isAbsentCodexIdentity` is the **one** rule (used by the popover, `codex list`, and `ranking.json` alike) for a declared-but-unprovisioned Codex identity (#135): `provider == .openai` with no stored token, no `codex_home`, **and** no local usage reading. The third condition only ever shrinks the absent set — a row this host has actually polled was demonstrably provisioned here, so it is never relabelled absent just because the feature shipped. The `hasStoredToken` input is likewise spelled **once**, as SQL, by `storedTokenCountSQL` (#169) — every consumer surface plus `openAIAccountCount` builds its subquery from it (passing the account-id expression its own query aliases, and `credentialsTableExists: false` when `oauth_credentials` is missing), so the shared rule is enforced by the code rather than by four hand-copied fragments agreeing. `oauth_credentials.is_active` is deliberately **not** part of that predicate: absence answers "was this identity ever provisioned here?", not "will it poll next cycle?", and `openAIAccountCount` — which fails closed because an undercount licenses the ambient home — shares the fragment. Absence is derived, never a stored column; `Account.isAbsent` is computed at load and absent rows sort last and can never be the menubar account. `accounts.codex_home` is nullable with **no** `DEFAULT` — NULL means "the ambient home", so every pre-migration row keeps its old behaviour untouched. It is host-local on purpose: `AccountSync` and `RankingExporter` both use explicit column lists, which is exactly what keeps a username-bearing path out of an export bundle and out of `ranking.json`. Keep it that way; never switch either to `SELECT *`.
  - `Sources/SQLiteDB.swift` - Minimal wrapper over system libsqlite3 (zero package deps). `readonly: true` is a lock-avoidance **hint**, not a hard "never writes" guarantee: a `SQLITE_OPEN_READONLY` connection cannot create the `-shm` a WAL database needs, and that refusal lands on the *first statement* (`SQLITE_CANTOPEN`), never on the open — so `Connection.init` probes with `PRAGMA schema_version` and escalates read-only → read-write (**no** `SQLITE_OPEN_CREATE`, so a typo'd `--db` errors instead of creating an empty database) → `file:…?immutable=1` only as a last resort **gated on the absence of a non-empty `-wal`**. `immutable=1` silently ignores WAL content, so it must never be reached before read-write.
  - `Sources/FileLogger.swift` - Debug log at `~/.claude-monitor/debug.log`
  - `Sources/AccountSync.swift` / `Sources/AccountSyncCLI.swift` - `claude-monitor accounts export|import`: multi-host sync of account records + credentials. Exports carry plaintext tokens — `--output` writes `0600` and warns either way. Imports match by email, preserve local ids, and skip records older than the local row.
  - `Sources/NaturalSort.swift` - Hybrid lexical/numeric ordering so `agent-10` sorts after `agent-9`. Digit runs compare by value without parsing to `Int` (significant-digit count, then lexically), so a run past `Int.max` can't overflow. Used for the Account column and as the tiebreak when usage figures are equal.
  - `Assets/` - App icon (`AppIcon.icns` + 1024px master PNG + `icon-master.source.json` generation recipe)
- `scripts/build-macos-app.sh` - Build script that compiles and creates the .app bundle (bundles the icon)
- `scripts/claude-monitor.service` - Sample systemd user unit for Linux headless mode
- `build/` - Build output (ClaudeMonitor.app and .zip)
