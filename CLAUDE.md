# LLM Monitor - Development Notes

## Build & Install

- Build with: `./scripts/build-macos-app.sh`
- The build script auto-detects the installed `claude-code` version (from `claude --version`, falling back to the npm global listing) and patches the User-Agent string in `AnthropicAPI.swift` before compiling.
- **Important:** When installing to `/Applications`, you must `rm -rf` the existing app bundle before copying. `cp -R` over a running macOS app does not replace the binary. The correct sequence is:
  ```
  osascript -e 'quit app "LLM Monitor"'
  sleep 2
  rm -rf /Applications/LLMMonitor.app   # (upgrading from 1.x: also rm -rf /Applications/ClaudeMonitor.app)
  cp -R build/LLMMonitor.app /Applications/LLMMonitor.app
  open /Applications/LLMMonitor.app
  ```

## Headless / Linux

- The same package builds on Linux (`swift build` with `libsqlite3-dev` installed) as a headless daemon for Loom hosts — no UI, same poll loop, same `usage.db`/`ranking.json` outputs. See README "Headless Mode / Linux".
- UI sources are fenced with `#if os(macOS)`; portable core must stay free of AppKit/SwiftUI/Combine/os.Logger. On Linux, `LinuxCompat.swift` shims `ObservableObject`/`@Published`, and `CSQLite/` maps the system libsqlite3 (macOS uses the SDK's `SQLite3` module).
- Entry points: `main.swift` (macOS, dispatches to `HeadlessRunner` on `--headless`) and `HeadlessMain.swift` (Linux, always headless). Flags: `--once`, `--interval <sec>`, `--version`, `--help`/`-h`. Subcommands: `accounts`, `codex`, `tokens`, `calibrate`, `selftest`. On macOS, `--version` is dispatched top-level in `main.swift` (works with or without `--headless`, never launches the GUI); bare `--once`/`--interval` (without `--headless`) fail fast with a stderr message instead of falling through to the GUI branch.
- Run the test suite with `swift build && .build/debug/LLMMonitor selftest` (exits non-zero on failure). CI runs it on macOS and Linux.
- To verify a schema migration against real data, copy the live DB first — `cp ~/.llm-monitor/usage.db /tmp/ && .build/debug/LLMMonitor selftest --db /tmp/usage.db`. `--db` **writes** to the path it is given; never point it at `~/.llm-monitor/usage.db`.
- Parse response headers via `extractAnthropicHeaders` (lowercased map), never `allHeaderFields` subscripts — those are case-sensitive on Linux.
- Verify Linux builds from macOS with the `swift:6.1` Docker image (`apt-get install libsqlite3-dev`, then `swift build`).
- **Swift 6 language mode is on package-wide** (`Package.swift`'s `swiftSettings` passes `-swift-version 6` to the `LLMMonitor` target — kept as an `unsafeFlags` override rather than bumping `swift-tools-version` to 6.0, so the manifest stays parseable by any 5.9+ SwiftPM). A plain `swift build` surfaces every strict-concurrency diagnostic **as long as the toolchain actually supports language mode 6** — i.e. Swift 6.0+ (Xcode 16+ on macOS, or the `swift:6.x` Linux images CI uses). This is a real toolchain constraint, not automatic: the `-swift-version 6` flag is *rejected outright* (`error: invalid value '6'`) by Swift 5.x compilers, including the macos-14 GitHub runner's **default** Xcode 15. That's why `.github/workflows/build.yml`'s `build-macos` job has a "Select Swift 6 toolchain (Xcode 16+)" step (`xcode-select` to the newest `/Applications/Xcode_16*.app`) before `swift build`; without it CI fails on the flag before compiling a single line. So: local and CI agree **once both are on a Swift-6-capable toolchain** — confirm your local `swift --version` reports 6.0+ (region-based isolation in newer point releases like 6.3.x can still *downgrade* a few diagnostics CI's pinned 6.0 hard-errors, so CI remains authoritative for the exact error/warning split). Narrowest-correct annotations are used throughout: `@MainActor` for state genuinely only ever touched from the app's one main-thread call path (`UsageStore`, `OAuthPoller`, AppKit window-controller caches, SwiftUI rows like `SummaryRow`, the CLI/headless entry points that drive them), `Sendable`/`@unchecked Sendable` for classes with real internal synchronization or no mutable state (`FileLogger`, `AnthropicAPIClient`, `OpenAIAPIClient`), and `nonisolated`/`nonisolated(unsafe)` only for pure helpers or genuinely single-threaded accumulators (documented at each site) — never a blanket suppression. Main-thread-delivered `@Sendable` closures (a `Timer` block, a `queue: .main` NotificationCenter observer) reach `@MainActor` state via `MainActor.assumeIsolated`, valid precisely because delivery is already on the main thread.

## Project Structure

- `menubar-app/LLMMonitor/` - Swift Package Manager project
  - `Package.swift` - Package manifest (zero package dependencies)
  - `Sources/main.swift` - macOS entry point, AppDelegate, popover/window management. `updateStatusButton`/`createStatsStyleImage` render the calibration step-change badge (#199) as a small dot beside the percentage — computed and shown only inside the same `!suppress` branch that already gates the percent readout on `AccountFreshness.shouldSuppressPercent`, so the badge disappears under the identical staleness rule rather than a second, possibly-drifting one.
  - `Sources/AppPaths.swift` - **The only way code finds the data directory** (`AppPaths.dataDirectory` / `path(_:)` / `databasePath`) and env overrides (`AppPaths.environment("X")` reads `LLM_MONITOR_X`, falling back to the pre-2.0 `CLAUDE_MONITOR_X`). Since the 2.0 rename (Claude Monitor → LLM Monitor), data lives in `~/.llm-monitor`. `dataDirectory` is a lazy static whose first access runs `migrateLegacyDataDirectory`, so the move happens before *any* entry point opens a file. The move renames a real `~/.claude-monitor` to `~/.llm-monitor` and leaves a **relative symlink** at the old name. It never merges or deletes: two real directories are a `.conflict`, reported on stderr and left alone. It must not log through `FileLogger` (whose own path comes from here). The symlink is an external contract, because loom-daemon reads `~/.claude-monitor` / `LOOM_CLAUDE_MONITOR_DIR`; remove it only once Loom reads the new path. Likewise `AccountSyncRemote.defaultRemoteBinary` stays `claude-monitor` (the one name both 1.x and 2.x peers answer to), `install-linux.sh` keeps a `claude-monitor → llm-monitor` symlink and retires `claude-monitor.service`, and CI attaches the release binary under both asset names. Never hardcode `~/.llm-monitor` or `homeDirectoryForCurrentUser` + a data-file name anywhere else. Running `selftest` on a real Mac triggers the real migration (it touches the logger); CI and the Docker path are safe.
  - `Sources/HeadlessMain.swift` / `Sources/HeadlessRunner.swift` - Linux entry point + UI-less poll loop (also `--headless` on macOS)
  - `Sources/LinuxCompat.swift` - `ObservableObject`/`@Published` stand-ins for Linux (no Combine)
  - `CSQLite/` - System-library target mapping Linux libsqlite3
  - `Sources/RateLimitWindow.swift` - Provider-agnostic rate-limit model (`AccountProvider`, `RateLimitWindow`, `RateLimitSnapshot`). Window kind is **derived from the window's duration**, never its position in the provider response, and every window is optional — an account may legitimately report no session window.
  - `Sources/UsageProviderClient.swift` - `UsageProviderClient` protocol + `ProviderCredentials` / `ProviderUsageSnapshot` / `ProviderAPIError` (aliased as `AnthropicAPIError`)
  - `Sources/AnthropicAPI.swift` - API client (usage, profile, token refresh); conforms to `UsageProviderClient`
  - `Sources/OpenAIAPI.swift` - OpenAI/Codex client: `GET chatgpt.com/backend-api/wham/usage` (never `/backend-api/codex/usage` — Cloudflare-challenged), `POST auth.openai.com/oauth/token` refresh, and `CodexAuth` (reads `~/.codex/auth.json`, honoring `$CODEX_HOME`). Access tokens live ~10 days; expiry comes from the token's own `exp` claim. **Never log a token or a raw response body** — `OpenAIUsageResponse.flatten` redacts PII/credential keys at *every* nesting depth before anything is archived or logged.
  - `Sources/CodexAppServer.swift` - `CodexAppServerClient`: reads Codex usage by spawning `codex -s read-only -a never app-server` and speaking JSON-RPC over its stdio, so **no OpenAI credential is read, stored, or refreshed by this app**. The only place in the package's poll path that spawns a subprocess (the other `Process()` sites are one-shot: `CodexCLI`'s `codex login --device-auth` for `codex provision`, `AccountSyncRemote`'s `ssh` for `accounts push`/`pull`, and a `pgrep` inside `SelfTest`). Framing is **newline-delimited JSON** (not `Content-Length`), replies **omit the `jsonrpc` member**, notifications have no `id`, and `windowDurationMins` is **minutes** (× 60 for `RateLimitWindow`). `-32600`/`-32601` mean *capability absent → fall back*, never *account unhealthy* — codex 0.46.0 returns it for every unknown method; an unauthenticated `CODEX_HOME` returns it too, disambiguated by `account/read`'s `account == null` — a decode failure on that same reply is a distinct `.protocolFailure`, never folded into `.notLoggedIn`. (Version requirement and the Homebrew formula→cask remediation for a stale 0.46.0 install: README.md "Adding an OpenAI (Codex) Account".) The `initialize` reply's `result.userAgent` (e.g. `codex_cli_rs/0.147.0`) is read back and logged once per resolved binary path/version via `flog.info` — a cache-and-log-on-change diagnostic, not a per-poll one, so a stale-formula fallback is operator-visible in `debug.log` without spawning a separate `codex --version`. Shutdown is stdin-close → SIGTERM → SIGKILL, guaranteed on every exit path (success, throw, or cancellation) via an explicit `do`/`catch` around the handshake rather than a `defer` (a `defer` block cannot itself `await`); the wait between escalation steps suspends via `Task.sleep` rather than busy-blocking a pool thread with `usleep`. Never call `Process.waitUntilExit()` off the main thread (it spins a CFRunLoop and hangs). `codex` is resolved to an absolute path from a candidate list with a `LLM_MONITOR_CODEX_BIN` override — `/usr/bin/env` fails in a Finder-launched bundle. `codexHome` is per-account (see `OAuthPoller`); a *registered* home that no longer exists on disk fails fast as `.homeMissing` **before** spawning, rather than letting codex answer `account: null` and reading as "needs login". `redactHomePath` collapses a home directory to `~` for every error string, because those strings are logged and persisted to `oauth_credentials.last_error` and a raw home path names a user.
  - `Sources/ZaiAPI.swift` / `Sources/ZaiCLI.swift` - z.ai (Zhipu) GLM Coding Plan provider (`AccountProvider.zai`) + its `llm-monitor zai import|add|list` CLI (`--dir`, `--key-file`, `--email`, `--db`; Linux-capable). `GET api.z.ai/api/monitor/usage/quota/limit` with a Bearer key. Wire facts, live-verified 2026-09-24: in each `data.limits[]` entry, **`usage` is the cap and `currentValue` the spend** (the names read backwards). The window length is `number × unit`, where unit `3` = hours and `6` = weeks; other codes are unverified and yield an unknown duration, never a guess. `nextResetTime` is **epoch ms** and is absent for an idle window. **Errors are HTTP 200** with `success: false` and the code in the body, so HTTP status alone must never be read as success. The response carries **no identity**, so the account id is `zai:<email>` (from the key file's `(account: …)` comment), else `zai:<label>`. It is keyed on identity rather than the key, so rotation rolls the credential in place. Keys are static, so they are stored like Anthropic tokens (`source = 'zai-key'`). `OAuthPoller.syncZaiKeyFiles` (run inside `syncFromAccountFiles`, i.e. every launch) re-registers only a key that changed, and is add-only. `ZaiKeyFile.scan` reads only `coding-plan-<label>.env` files with a `ZAI_API_KEY=` line, so opencode's `ZHIPU_API_KEY` copy in `coding-plan.env` never registers a duplicate. The snapshot writes derived `session_status`/`weekly_status`/`overall_status` into the raw blob, so `RankingExporter.mapStatus` reports a spent key as `exhausted`, not `available`. Only numeric/enum fields are archived, and a key is never printed or logged.
  - `Sources/SubprocessIO.swift` - The two things every `Process()` call site in this package needs to get right, spelled once (#202): `SubprocessIO.ignoreSIGPIPE()` (must be called before writing to any child's stdin — a child that exits before reading, e.g. `ssh` on a refused connection or `codex` rejecting a CLI argument, leaves the parent writing into a pipe with no reader, and at SIGPIPE's default disposition that kills the whole process with no diagnostic) and `PipeDrain`, a class that reads one child pipe to EOF on a dedicated blocking-read thread rather than via `FileHandle.readabilityHandler`. The callback form is unreliable on Linux: swift-corelibs-foundation's `readabilityHandler` is backed by a libdispatch read source, and when a child writes and then exits, the kernel can hand the source its data *and* its hangup in the same wakeup — the source fires once with the bytes and is torn down, and the terminating empty-chunk callback that was supposed to signal EOF is never delivered. That is invisible to a child that writes nothing before exiting (which is why it stayed hidden for so long) and fatal to one that does: the old drain's `waitForEOF()` was an unbounded semaphore wait, so a test or a real `accounts push`/`codex app-server` call against a fast-failing child could hang forever (#202 — the documented `swift build && .build/debug/LLMMonitor selftest` Linux verification path could not complete in a stock `swift:6.1` container even though CI's identical image passed, because CI never got unlucky on the race). `read()` returning 0 is EOF unconditionally on every platform, so a dedicated thread has no such contract to get wrong. Used by both subprocess call sites that write to a child's stdin — `AccountSyncRemote.runProcess` and `CodexAppServerClient`'s handshake — so the next one that spawns a `Process()` inherits both rules instead of re-deriving either slightly wrong.
  - `Sources/CodexCLI.swift` - `llm-monitor codex provision|add|list|import` (one-shot CLI, no `--headless` needed, works on Linux). `codex add --home <path>` registers an OpenAI account **by its `CODEX_HOME`** and stores no token — it reads only `tokens.account_id` from that home's `auth.json` (via `CodexAuth.accountId(inHome:)`, deliberately *not* `CodexAuth.load`) and asks `codex` itself for identity/usage. `codex provision <label>` (#133) collapses home-create + `codex login --device-auth` + registration into one command — it creates/reuses `~/.codex-<label>`, drives the interactive login (never automates or bypasses it), then calls the exact same `OAuthPoller.registerCodexHome`/`normalizeCodexHome` `add` uses. `codex list` reports each home's live login state, plus **absent** (#135) for a declared-but-unprovisioned identity — never probed (there is no home to ask, and asking the ambient one would report a stranger's login state as this row's) and printed with the exact `codex provision <label>` that fills the gap. All three accept `--db`. A home path is printed to stdout (that's the point of `list`) but never to `debug.log`.
  - `Sources/TranscriptImporter.swift` / `Sources/TokensCLI.swift` - Claude Code transcript → `token_usage`/`token_sessions` ingest (#197) plus its `llm-monitor tokens sync` CLI (`--root`, `--limit N`/`--all`, `--db`; works on Linux, no `--headless` needed). A port of the pre-v2.0 native host's `syncTokenUsage`/`processJsonlFile` (deleted in `b9db622`), which is why both tables keep the **legacy column shapes byte-for-byte** — an old host still holds ~85k rows there, so `applySchema` must adopt them, never reshape them. Three things the deleted importer got wrong are deliberately reversed: the walk is **recursive** (transcripts now nest as `<project>/<session>/subagents/agent-*.jsonl`), `agent-*.jsonl` is **not excluded** (subagent spend is real spend, and sidechain records count), and the scan is **incremental** — a file is opened only when its mtime beats `token_sessions.last_import_ts`, which is written as the file's *observed mtime* rather than the import wall clock so a file appended mid-read is re-read next run. The mtime comparison carries a 2 ms tolerance because an ISO-8601 stamp is millisecond-precision while an mtime is not; an exact `>` would re-read the whole tree every run and the scan would not be incremental at all. A per-run file budget (default 2000, newest first) keeps a cold host's five-figure backlog from stalling a poll cycle — it *defers*, never drops, and reports the remainder. **`inferred_account_id` stays NULL**: transcripts carry no account identity, and the old last-polled-account inference is noise across ~20 staggered accounts; `token_sessions.parent_session_id` (the one additive column) records the session a subagent transcript belongs to so an external mapping (rjwalters/loom#8059) can join `COALESCE(parent_session_id, session_id)`. **Privacy is structural, not a rule to remember**: `TranscriptRecord` has no field for `message.content`, so no decode path exists by which a message body could reach the database or `debug.log`; every path that is logged or stored goes through `redactPath`. Runs from `OAuthPoller.syncTranscriptTokensIfDue` on a **1-hour** cadence (vs. the 10-minute usage poll), on a detached task because a cold scan is seconds of filesystem work that must not sit on the main actor.
  - `Sources/QuotaCalibration.swift` / `Sources/CalibrationCLI.swift` - Daily quota-calibration series (#198, phase 2 of #196) + its `llm-monitor calibrate` CLI (`--days`, `--format json|csv`, `--scope`, `--min-points`, `--no-recompute`, `--db`; Linux-capable, no `--headless`). Joins the two halves the app already collects — `usage_history.weekly_all_percent` (how much quota went) and `token_usage` (how many tokens that was) — into the only figure that matters downstream (rjwalters/loom#8063): **what one weekly rate-limit point costs**. Four decisions carry the correctness of that number and must not be quietly undone. **(1) Rows are ordered by `(parsed instant, rowid)`, never by timestamp text.** The reset path in `writeUsageToDB` emits a synthetic carry-forward row, a synthetic `0`, and the real row — and the last two share a whole second, so timestamp-only ordering leaves them unordered; get it wrong at a day boundary and a day's consumption migrates across midnight and manufactures a spurious positive delta on the next day (`testCalibrationResetOrderingTieBreaksOnRowid` fails 19/3 → 7/15 if the tiebreak is dropped). The instant must be *parsed* because this codebase writes ISO 8601 both with and without fractional seconds and `…:09.500Z` sorts *below* `…:09Z` as text while being the later instant. **(2) Synthetic rows are kept, not filtered** — the carry-forward row is what turns a reset into one negative delta instead of a lost increment. **(3) `raw_tokens` ≠ cost.** A cache read bills at 0.1× an input token and a cache write at 1.25×, so cost is accumulated *per model while the model is still known*; `TokenAggregate` exists to make it impossible to carry totals without the cost they were priced at, because re-pricing collapsed totals at one "representative" rate is precisely the plausible-but-wrong number this feature exists to catch. **(4) Per-account token attribution reads `token_sessions.override_account_id` only** (inherited by subagent transcripts through `parent_session_id`), never `inferred_account_id` — that column *is* the deleted native host's last-polled-account guess, and a legacy database's stale values must never be promoted back into a cost figure. An account row still carries that account's own points; only its token/cost columns go absent. Every optional value is **omitted, never zeroed** (`ranking.json`'s contract): an absent `cost_usd_per_point` read as 0 reports a quota that became free. A day below `--min-points` (default 5 — one weekly point is the measurement quantum) keeps its point count and drops its ratios. Prices live in `currentWeights`, a **dated** table whose `version` is stamped on every row; when Anthropic re-prices, add a new dated table rather than editing in place, and an unrecognized model id is priced at the Sonnet-class fallback *and reported* rather than billed at zero. Pool rows always carry `accounts_reporting`/`points_per_account` because the denominator genuinely moves (19 → 15 → 19 → 20 across one measured window). OpenAI accounts are excluded outright — their weekly percentage is a share of a different quota and their spend is not in Claude Code transcripts. `recompute` is idempotent by construction: DELETE the window + INSERT inside one transaction, nothing read back to decide what to write, so the 1-hour `OAuthPoller.recomputeQuotaCalibrationIfDue` cadence cannot accumulate drift. That hook is deliberately **not** folded into `syncTranscriptTokensIfDue` — a host without Claude Code installed still has a meaningful points series, and gating on an import that can never succeed there would leave the table permanently empty, which is the complaint #196 was filed about. **`evaluateStepChangeAlerts` (#199, phase 3 of #196)** is the pure, portable-core step-change rule that watches the pool-scope `rawTokensPerPoint` series `recompute` produces: a `recentWindowDays`-trailing (default 3) average at/below `1 / threshold` (default 1.5) of the `baselineWindowDays`-trailing (default 14) median, evaluated over the `baselineWindowDays` days immediately **preceding** the recent window (non-overlapping with it, so a step can't dilute the very baseline it's judged against). It is **direction-aware** — only a *decrease* ever alerts, since a rise (including a depressed regime recovering) is the healthy direction — and **edge-triggered with a latch**: an alert fires once, when the ratio first crosses the threshold, not on every subsequent day it stays depressed, and can only fire again after the ratio genuinely recovers above the threshold and later drops a second time. Both properties are required to reproduce the reference series correctly (`SelfTest.calibrationReferenceSeries`, reused via `syntheticTokensPerPointRows`'s flat-workload-assumption reciprocal of `pointsPerAccount`): exactly one alert on 2026-09-06, with no re-trigger on the 2026-09-10 partial reversion. `OAuthPoller.evaluateCalibrationAlerts` runs it after every `recompute` and is the **entire** alert surface in headless mode (a `flog.warning` line, logged once per newly-found alert day, never repeated for an unchanged one) — on macOS, `main.swift` additionally reads the same `calibrationAlerts`/`hasActiveCalibrationAlert` state to render a menu-bar badge.
  - `Sources/CLIArgs.swift` - Shared argument-parsing helpers for the one-shot subcommand CLIs (`CodexCLI`, `AccountSyncCLI`): the `--db <path>` and `--help`/`-h` option cases plus the `fail(_:) -> Never` parse-error reporter live here once (#176). A plain `enum` namespace of static pure functions, like `NaturalSort`/`PercentSeverity`.
  - `Sources/OAuthPoller.swift` - Per-provider usage polling (Anthropic ping / OpenAI usage GET), token add/import, per-account Codex-home registration, Fable probes (Anthropic only). Absent windows are stored as NULL, not 0, for non-Anthropic providers. `pollOpenAI` is a two-tier ladder ordered by how little credential handling each rung needs: `codex app-server` → bearer read from `auth.json` at request time — there is no stored-credential fallback below it (#104). A merely *unavailable* tier falls through silently; only the last tier's own failure sets a status. **Both tiers read the polled account's own `accounts.codex_home`**, resolved by `resolveCodexHome` into `.explicit` (registered home — a fresh `CodexAppServerClient` per account), `.ambient` (no registered home and no sibling that could own the inherited one), or `.ambiguous` (≥2 OpenAI accounts and this one has no home ⇒ **no** home may speak for it — both tiers are skipped and the poll reports the most actionable pending failure). Counting candidates rather than comparing emails is what closes the NULL-email attribution gap; `identitiesConflict` survives only as belt-and-braces for a re-logged-in home. **`loadActiveCredentials` is the only enumeration the poll loop uses** — it admits token-free rows (`access_token IS NULL`) whose account has a `codex_home`, or a home-registered account would never poll. That clause keys on **`accounts.codex_home`, never on `source`** (#194): `'codex-home'` is a descriptive tag `saveCodexHomeAccount` happens to write, and a legacy `source = 'codex'` row polls perfectly well as long as it has a token or a home — diagnosing a stale OpenAI account from `source` is reading the wrong column. The price of that deliberate narrowness is the **stranded** row (#194): token-imported, no home, and its token nulled by #123's healing migration, so it satisfies neither clause, never reaches `pollOpenAI`, and gets no status at all. `strandedCodexCredentials`/`reportStrandedCodexIdentities` (called from `pollAll`/`pollDue` beside that enumeration) give exactly those rows a voice — an in-memory `.missing` + `strandedCodexMessage` every cycle, logged and persisted to `last_error` once per process, and deliberately **without** touching `last_poll_at`, because a diagnostic that claimed the row was polled would silence the staleness backstop (#148) it exists to explain. It is diagnostics only: the stranded row stays out of the poll set, since reviving it would mean restoring the stored-credential fallback #104 removed. For the same reason `pollOpenAI`'s exhausted-ladder report is `exhaustedTiersMessage(home:)`, not the old `"No access token"` — an OpenAI row *never* has a stored token by design, so that sentence named no cause and pointed at a fix that no longer exists. **Declared identities (#135)**: `exportAccountsEnv` emits a tokenless Codex row as *identity only* (`ACCOUNT_EMAIL_N` + `ACCOUNT_PROVIDER_N` + `ACCOUNT_HOME_LABEL_N`, **no** `ACCOUNT_KEY_N`) — a home *label*, never a path, because a path names a user; `parseAccountPairs` accepts a keyless entry only for a non-Anthropic provider; `declareCodexIdentity` writes the placeholder row (no credential row at all — its absence *is* the state) and is a no-op when the identity already exists, so a paste can never downgrade a working account. `syncFromAccountFiles` honors keyless entries too — a headless Linux host has no popover, so `~/.llm-monitor/accounts.env` is its only env-transfer surface; safe on an every-launch cadence precisely because the declaration is add-only and idempotent. `openAIAccountCount` **excludes** absent rows: counting them would flip a legitimately-ambient single-account host to `.ambiguous` and stop it polling — i.e. the bookkeeping layer would break what it books.
  - `Sources/AccountFreshness.swift` - Cause-independent staleness backstop (#148): the single rule every display/ranking path uses to decide whether a reading is too old to present as current, regardless of why it stopped updating. Lives in the portable core so `UsageStore` ranking/selection, the popover freshness dot, and `SelfTest` all apply the identical threshold.
  - `Sources/SelfTest.swift` - `LLMMonitor selftest`: portable-core assertions (window model, schema migration, OpenAI wire mapping + PII redaction, `ranking.json` provider field) with no network/credentials. Run in CI on both macOS and Linux; there is no XCTest target because the package has zero dependencies. `--wire <path>` decodes a captured `/wham/usage` body offline (prints only derived numbers, never identity). `--codex` opts in to one real `codex app-server` handshake against the installed binary (needs a logged-in home; skipped by CI).
  - `Sources/RankingExporter.swift` - Emits `~/.llm-monitor/ranking.json`. Every account carries `provider`; `schema` stays **1** because the fields are additive. A `provider: openai` account may omit `utilization["5h"]` — consumers must read a missing key as *unknown*, never 0. An **absent** identity (#135) adds `"absent": true` and is emitted with `"status": "blocked"` and *no* `utilization`/`resets`/`updated_at`, so a consumer ignorant of the new key still excludes it from its pool.
  - `Sources/UsagePopoverView.swift` - Summary-table popover, sortable headers, add-account dialog. An **absent** row (#135) renders greyed with an `AbsentBadge` (which prints `CodexCLI.absentLabel` itself, not a second literal) and blank percentages; Copy emits Codex accounts identity-only, and Paste's replace semantics are armed **only** by credentialed entries — a declaration must never delete a provisioned home.
  - `Sources/PercentSeverity.swift` - Severity band for a percent-used value; centralizes the >95 / >=90 boundaries so the popover table, chart window, and menu-bar icon can't drift out of sync. The calibration step-change badge (#199, `main.swift`) is a deliberately separate visual channel (a small dot, not a fourth color) precisely so it never has to fit into — or compete with — this file's three-band palette.
  - `Sources/UsageChartView.swift` - Per-account usage-history chart window. `ChartMode` (#199 adds `.calibration` alongside `.percent`/`.tokens`) is gated per-case into `availableChartModes` rather than always offering all three — `.tokens` and `.calibration` only appear in the segmented picker once the account actually has data for them (`hasTokenData`/`hasCalibrationData`), the same pattern the pre-existing `.tokens` gate already used, so an account with neither is never offered a mode with nothing to plot. The calibration series (`UsageStore.loadCalibrationHistory`, one point per UTC day from `quota_calibration_daily`) is read-only here — recompute happens on `OAuthPoller`'s slow cadence, matching `loadTokenHistory`/`loadNamedLimitHistory`'s role. Its token series (#201) falls back to `UsageStore.loadHostTotalTokenHistory` — a host-wide, account-agnostic total — whenever `loadTokenHistory(for:)` finds nothing attributed to the account being shown but `hasAnyTokenUsageData()` says the host has ingested spend anyway (the steady state since #197, which deliberately leaves `token_sessions.inferred_account_id` NULL). `tokenDataIsHostTotal` threads that distinction through the view so the fallback is always labeled "(Host Total)" with an explanatory caption, never presented as this account's own history — once rjwalters/loom#8059's external session_id → account_id mapping lands and populates `override_account_id`, `loadTokenHistory(for:)` starts returning attributed data again and the fallback stops firing on its own. The two interact in exactly one place, `chartModeHeadline`: the host-total label belongs to `.tokens` alone, so `.calibration`'s headline is never qualified by it (a calibration ratio is a pool-scope figure, not this account's attributed spend).
  - `Sources/RollTokenView.swift` / `Sources/TokenRoller.swift` - Roll Token wizard + revoke-script generator. The workflow depends on undocumented, web-session-cookie-authenticated `claude.ai/api/oauth` endpoints; if they change, `TokenRoller.revokeAllScript` is the single place to update (see README "Rolling a Token").
  - `Sources/UsageStore.swift` - SQLite-backed data store, account/usage models. `isAbsentCodexIdentity` is the **one** rule (used by the popover, `codex list`, and `ranking.json` alike) for a declared-but-unprovisioned Codex identity (#135): `provider == .openai` with no stored token, no `codex_home`, **and** no local usage reading. The third condition only ever shrinks the absent set — a row this host has actually polled was demonstrably provisioned here, so it is never relabelled absent just because the feature shipped. `isStrandedCodexIdentity` (#194) is that same rule with the third condition **flipped**, and the pair is exhaustive: a row with no credential path here is either absent (never provisioned) or stranded (provisioned, then left unpollable by #123's token-nulling migration). Keep them defined together — the only thing separating them is `hasLocalReading`, and they print different remediations (`codex provision <label>` vs re-registering the home this host already had). The `hasStoredToken` input is likewise spelled **once**, as SQL, by `storedTokenCountSQL` (#169) — every consumer surface plus `openAIAccountCount` builds its subquery from it (passing the account-id expression its own query aliases, and `credentialsTableExists: false` when `oauth_credentials` is missing), so the shared rule is enforced by the code rather than by four hand-copied fragments agreeing. `oauth_credentials.is_active` is deliberately **not** part of that predicate: absence answers "was this identity ever provisioned here?", not "will it poll next cycle?", and `openAIAccountCount` — which fails closed because an undercount licenses the ambient home — shares the fragment. Absence is derived, never a stored column; `Account.isAbsent` is computed at load and absent rows sort last and can never be the menubar account. `accounts.codex_home` is nullable with **no** `DEFAULT` — NULL means "the ambient home", so every pre-migration row keeps its old behaviour untouched. It is host-local on purpose: `AccountSync` and `RankingExporter` both use explicit column lists, which is exactly what keeps a username-bearing path out of an export bundle and out of `ranking.json`. Keep it that way; never switch either to `SELECT *`. `applySchema` also owns the two transcript-token tables (`token_sessions`, `token_usage`, #197) — reproduced verbatim from the pre-v2.0 native host so an existing host's rows are adopted rather than reshaped; add to them via `addColumnIfMissing`, never by editing that `CREATE TABLE IF NOT EXISTS` block (it is a no-op on exactly the databases that matter most). `applySchema` likewise owns `quota_calibration_daily` (#198) — a **new** table, deliberately not the legacy `quota_calibration` the native host declared: that one's `account_id` is `NOT NULL` (which cannot express a pool-level row) and `CREATE TABLE IF NOT EXISTS` cannot reshape an existing table, so reusing the name would leave a fresh install and a legacy install disagreeing about the columns. Its uniqueness guard is an **expression** index on `(day, scope, IFNULL(account_id, ''))`, not `PRIMARY KEY (day, scope, account_id)`, because SQLite does not enforce uniqueness across a NULL PRIMARY KEY column and pool rows have a NULL `account_id`. `hasTokenData(for:)`/`loadTokenHistory(for:)` answer only the *attributed* question (#201) — since #197 that's `false`/empty for every account on a fresh import, because `inferred_account_id` is deliberately left NULL. `hasAnyTokenUsageData()` and `loadHostTotalTokenHistory` are the account-agnostic pair that keep that from reading identically to "no data was ever ingested": the former is a bare `token_usage` row count, the latter sums every row regardless of attribution. Neither guesses an owning account — that's the last-polled-account inference #197 removed on purpose — so every caller must label the result as a host total, never as a specific account's history; `UsageChartView`'s `tokenDataIsHostTotal` flag is the one consumer today.
  - `Sources/SQLiteDB.swift` - Minimal wrapper over system libsqlite3 (zero package deps). `readonly: true` is a lock-avoidance **hint**, not a hard "never writes" guarantee: a `SQLITE_OPEN_READONLY` connection cannot create the `-shm` a WAL database needs, and that refusal lands on the *first statement* (`SQLITE_CANTOPEN`), never on the open — so `Connection.init` probes with `PRAGMA schema_version` and escalates read-only → read-write (**no** `SQLITE_OPEN_CREATE`, so a typo'd `--db` errors instead of creating an empty database) → `file:…?immutable=1` only as a last resort **gated on the absence of a non-empty `-wal`**. `immutable=1` silently ignores WAL content, so it must never be reached before read-write.
  - `Sources/FileLogger.swift` - Debug log at `~/.llm-monitor/debug.log`
  - `Sources/AccountSync.swift` / `Sources/AccountSyncCLI.swift` / `Sources/AccountSyncRemote.swift` - `llm-monitor accounts push|pull|export|import`: multi-host sync of account records + credentials. Exports carry plaintext tokens — `--output` writes `0600` and warns either way. Imports match by email, preserve local ids, and skip records older than the local row; `importBundle` **creates** the store (parent directory, file, schema) when the host has none, because a never-launched fresh worker is exactly the host an import is most needed on — `exportBundle` keeps its own `databaseMissing` guard, since a host with nothing to read must not emit an empty bundle that looks like a successful export. `push`/`pull` (#188) are the primary path: the bundle is serialized **into memory** and written to the stdin of `ssh HOST 'llm-monitor accounts import -'` (or read from the stdout of a peer's `accounts export`), so no plaintext-token file exists on either side — there is deliberately no `write(to:)` anywhere on that channel, and `selftest` pins it by scanning the whole scratch tree for the token. Every host in a `push` is attempted even after one fails; the exit status is non-zero if any did — and that holds for the case that actually breaks it, a host whose `ssh` exits *without reading its stdin* (refused connection, bad host key): **SIGPIPE is ignored** (`runProcess` installs `SIG_IGN` once) and the bundle goes out through the throwing `write(contentsOf:)`, so the EPIPE a fleet-sized bundle takes mid-write is a per-host failure reported as ssh's own `exit 255` rather than a signal that kills the whole fan-out with a bare 141. `RemoteResult.inputWriteFailed` keeps the two apart: a non-zero child status always wins the diagnostic (the broken pipe is the symptom, ssh's status the cause), and a *clean* exit with a truncated bundle is still a failure. `--dry-run` sends **zero bytes** of bundle (it only asks the far side for `--version`), and `--then-loom` chains `loom-daemon tokens import-from-monitor --shared` with `&&`, never `;`, so a failed import cannot re-publish the old tokens as if it had worked. `ssh` is resolved to an absolute path with a `LLM_MONITOR_SSH_BIN` override (the same pattern as `LLM_MONITOR_CODEX_BIN`, and the seam `selftest` points at a stub).
  - `Sources/NaturalSort.swift` - Hybrid lexical/numeric ordering so `agent-10` sorts after `agent-9`. Digit runs compare by value without parsing to `Int` (significant-digit count, then lexically), so a run past `Int.max` can't overflow. Used for the Account column and as the tiebreak when usage figures are equal.
